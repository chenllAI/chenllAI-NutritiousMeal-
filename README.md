# 营养餐经营报表

某医院营养餐的经营情况可视化报表，每日/每周自动生成。

## 报表说明

报表为**自包含 HTML**，无 CDN、无外部依赖，可直接在浏览器打开或离线传阅。

- `日报-YYYY-MM-DD.html` — 单日核心指标（订单数 / 金额 / 下单用户数 / 客单价，环比昨日与上周同一天）、餐次分析、预订用餐日分布、商品（套餐）分析、**病区分析**、近 14 天趋势、订单状态拆分、订单明细。
- `周报-YYYY-MM-DD_至_YYYY-MM-DD.html` — 自然周（周一至周日），在日报口径上增加**日期 × 餐次矩阵**与每日三餐堆叠趋势，环比前一周。
- `区间报告-*.html` — 自定义区间的滚动周报，用于「上周四 ~ 本周三」这类非自然周统计。

## 病区分析

订单的收货地址带院内位置，报表把它解析成**护理单元**（如「第三十二护理单元」）与**楼栋-楼层**（如「北楼-13F东」）两级，用于观察餐食覆盖到哪些科室。日报除当日分布外，另附近 14 天累计排行作背景。

展示粒度**只到护理单元与楼栋-楼层**：地址中能定位到具体病床的床号、病室号**一律不进入报表**，也不参与任何统计。地址只写到床号的订单会归入「未标注护理单元」，与真实病区分开统计。

## 数据脱敏

本仓库中的报表**均为脱敏版本**，可对外公开。原始报表含住院患者个人信息，仅保留在生成方的本地环境中。

脱敏规则如下（此处只描述规则，不列举任何原始值）：

| 字段 | 处理方式 |
| --- | --- |
| 收货人姓名 | 仅保留姓氏，名字部分以 `**` 替代 |
| 手机号 | 仅保留前三位，后四位去除 |
| 收货地址 | 明细表中的地址列整格移除，统一替换为 `某医院` |
| **病区** | 病区分析按**护理单元**聚合成图表，病区名保留真实值；**不含床号、病室号** |
| 床号 / 病室号 | 不进入任何字段与统计，并由校验脚本兜底拦截 |
| 用户 ID | 替换为稳定假名 `U-nnnn` |
| 订单号 | 替换为稳定假名 `ORD-nnnn` |
| 医院名 / 品牌名 | 统一替换为 `某医院` / `某营养餐供应商`，并去除所在地名 |

订单号与用户 ID 使用**稳定假名**：同一个真实值在所有报表中映射为同一个编号，因此跨日报、周报仍可交叉核对，但编号本身不携带任何原始信息。

所有汇总数据、图表、趋势与结论均为真实值，未作任何改动。

## 说明

- 报表中的金额单位为人民币元。
- 统计口径以生成方内部规范为准，本仓库仅发布产物。
